# Calorie Agent 协作约定

需求与产品语义见 `REQUIREMENTS.md`，跨模块接口见相关 `contracts/`。
按当前任务读取相关内容；已确认的新决定同步到原文档，历史计划和未解决项不自动成为新任务。
实际部署、验收状态及未解决项统一见 `reports/LATENCY_DELIVERY.md`；规格描述应达到的行为，不代表已经通过验收。

## 实现边界

- 飞书＋COS 存储与执行约定见 `LATENCY_OPTIMIZATION_SPEC.md`：COS 保存运行状态及已提交业务事实，Bitable 后台归档；LLM 负责理解和规划，营养计算与读写由工具执行。
- 预设行为集中在 `agent/policy/presets.py`；节点消费策略结果，不增加旧候选版本分支。
- COS 与 Feishu/Bitable HTTP 仅在 `agent/storage/`；工具实现和注册在 `agent/tools/`。
- 业务数字须有工具事实依据；知识回答数字须出现在检索原文中。
- 成功回复依据对应已提交业务结果；收件、待执行和待确认不代表业务成功，飞书归档进度单独确认。
- 创建防重及状态更新遵循 `contracts/bitable_schema.md`。
- 复用现有实现，不新增无用转发文件、演示回复或与任务无关的抽象。

## 同步维护

- 改表字段、幂等键：更新 `contracts/bitable_schema.md`。
- 改 Store 接口：更新 `contracts/tool_protocol.md`，同步生产 Store 与 FakeStore 的业务语义。
- 改 trace 形状：更新 `contracts/trace_schema.md` 及实际消费者。
- 增删工具：同步 schemas、registry、需求能力清单，并补相关 eval 用例。
- 控制台仅监听 127.0.0.1；其依赖、DSH 数据和构建产物不进云函数包。

## 验证

- 以当前任务和有效规格确定要证明的结果及最小验证范围。纯文档只核对准确性与引用，局部改动运行相关用例；全量仅在规格明确要求或相关组不足以覆盖实际影响时运行。
- 复用可追溯的已有证据：确认其对应的相关实现、配置、来源数据和会话状态仍支持当前判定。新线程、换执行者、独立审查或进入收尾阶段，本身不使证据失效。
- 复验须有相关变更、前次失败、证据缺失或具体疑点，简述触发原因及受影响范围。确认测试注册或构建标识时使用直接检查或最小用例，不因此重跑整组业务；基线仅在需要区分既有故障时运行。
- 涉及来源规模、迁移或会话恢复时，在必要场景内覆盖相关真实输入与旧状态，优先改进代表性，不堆叠同类干净样例。评测统一从 `harness/eval/runner.py` 运行，支持 `--smoke`、`--case ID` 和全量。

## 收尾

- 当前任务约定的结果及必要验证已满足、没有影响该结果的未决问题时结束，不为“再放心一次”追加测试、审查或优化。用户缩小范围或要求停止时，按实际结果收尾，保留未完成项及原判定，不降低门槛或将失败改为通过。
- 交付说明实际改动、复用或新取得的证据及未解决事项，区分已实现、已部署、链路可用、业务正确与验收完成；health、ACK或发送成功不能单独证明业务正确。
- 失效的过渡指令删除或标为历史；已由工具可靠解决的问题不再叠加同义规则。
